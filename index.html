Trading Co-Pilot — a trading desk that argues back
local only · one machine · one copy

Every rule here has a receipt.

A single-trader co-pilot for Micro Nasdaq and Micro Gold futures. It watches a live TradingView chart, reads the broker panel, and holds the line on a rulebook where no number exists without the day it changed and what that day cost.

The rulebook is a data file, and it remembers

Every discipline rule lives in app/rules.json, never in code. Each value sits beside a comment recording the evidence that set it. Pick one.

What it actually does during a session

No build step, no framework. One Node process on port 7433, one WebSocket, a plain browser page, and a Chrome DevTools link into TradingView Desktop.

reads the chart

Watchers poll the live chart for engulfing candles on 1H, 30M, 15M and 5M, fair-value gaps, swing-failure patterns, and the mechanical accumulation–manipulation–distribution phase.

A single chart lock serialises them, because there is one TradingView connection and a watcher that steals the chart mid-read leaves it somewhere you did not put it.

reads the broker

Position size, open orders and day P&L come straight off the connected broker panel, folded by balance-delta at flat.

The app also cross-checks its own ledger against the broker and reports the gap rather than quietly picking a winner.

argues

Nine personas on one model: a coach, a voice coach, a scalper, an analyst, a refuter that attacks the analyst's case, a judge that settles it, a Power-of-3 reader, a post-session analyst, and the loop.

Only the judge may issue a trade ticket, and only after the refuter has had its turn.

remembers

Every line that appears in the chat pane is written to an append-only archive that is never trimmed. Repeated mistakes and repeated good trades are filed as episodes with a citation back to the record that proves them.

The loop speaks only when something is a repeat, and it can quote what it told you the last time.

explains

A losing day gets one cause, not a list. Trades are walked in sequence to find the turning point — the first loss followed by a real size escalation — and every losing trade is attributed to exactly one cause, so the dollars add up to the day.

A day of clean losses is given no cause at all.

stops you

Checklist gate, size cap, contracts-per-day ceiling, cooldown after a loss, a size-freeze that blocks sizing up while you are down, tiered daily loss alarms, the day stop, and a hard flatten at 3am.

Skipping the pre-session checklist is a hard no-go, ranked with the daily stop.

Clear — 2 of 10 trades day −$84.20
Cooldown 14:32 no entries
News blackout — red folder no entries
Stopped — done for the day type “i am done”

Two things can send a real order

Everything else in this repository is advisory. These two are not.

You confirm a ticket. The judge returns a go verdict carrying a machine-readable ticket. It appears on screen. Nothing happens until you press confirm, and the gate that checks it has no override path.

The oversize guard acts unasked. If it reads a position above your cap twice in a row, it sends a reducing order — never a closing or flipping one — capped at six actions a day with a thirty-second cooldown, and logs the size it saw, the order it sent and whether the broker took it.

Both live behind a separate launcher. Start the app the ordinary way and the guard can only sound the alarm. START CO-PILOT (LIVE ORDERS).bat is a deliberate act.

What is not verified

This page would be worth less without this part. The repository keeps built and live-verified as separate words.

unverified

The live P&L fold has never been checked against a real closed trade with non-zero P&L. Every live size and P&L figure sits on top of it.

broken

Setting a price on a TradingView alert does not take. It creates the alert at the current market price instead, so the function fails loudly rather than reporting a success it did not achieve.

shadow only

The ADX breakout playbook records what it would have done and can place nothing. It has never traded.
